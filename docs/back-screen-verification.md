## 发现并修复的问题

| 原问题 | 修复 |
| --- | --- |
| connect 返回 false 或 isError 仍缓存为设备可用 | 明确失败阻止后续调用；成功载荷未定义，仍兼容返回 undefined 的连接 |
| 空值或空对象回执也报告成功 | 拒绝空回执；兼容中文字符串、text、MCP content 和明确成功标记，不依赖 structuredContent |
| 帧只检查长度 | 逐项验证整数 0–255，拒绝稀疏数组、越界、NaN 等；连接前复制帧，防止异步等待期间载荷被修改 |
| 失败缺少可定位诊断 | 仅输出连接器、固定操作／能力名、固定分类及数字错误码，不输出原始回执、异常、帧或凭据 |
| 连接挂起会卡住整个首页加载 | 背屏连接与本地记录加载分离，前屏仍能使用和计时 |
| 原生请求挂起无失败提示 | 每条请求 10 秒诊断超时后停播，保留实际占用直到真实 Promise 结束，不伪装取消 |
| 等待中重复重试可能另起连接 | 首次连接与失败后的重连都纳入同一命令占用；超时前后都禁止另起连接；旧连接迟到结果不覆盖新状态，旧命令组不继续发送 |

超时不等于原生取消：已发送的请求仍可能在设备上完成。必须等待原请求结束后，才能手动重试最新目标。没有取消契约时，不承诺重试能强行终止旧请求。

## 预设功能能否实现

| 功能 | 判断与设备边界 |
| --- | --- |
| 孵化阶段、裂纹、问号与宠物帧 | 有对应接口，本地调用链通过；实际接收、图案、方向及亮度须真机 |
| 每约 12 秒一次、帧间至少 1 秒的短动画 | App 前台可调度，符合资料建议的至少 100ms 帧间隔；真实延迟、刷新与功耗须真机 |
| 到期振动与翻面揭晓 | 业务触发存在；振动、传感器、前屏常亮属于现有 Capsule 整机能力，背屏资料不能证明这些能力的实机效果 |
| 收藏选择与停止展示 | 本地状态与顺序通过；clear 后紧接 sleep，最终请求是熄灭，不能描述为恢复并持续显示 agent |
| 隐藏后返回 | 可重算当前阶段并重发，不补播过时动画；壳事件、进程恢复和系统抢占须真机 |
| 宠物一直亮着 | 当前实现不保证；wake 只即时点亮，auto 会超时灭，always/custom 是系统策略。未假设推帧能延长 auto 的亮屏时间 |
| 锁屏／后台持续动画及准时触发 | 不承诺；显示模式不能保证 WebView 定时器或进程在后台运行，本项目隐藏时主动停播 |
| 背屏触摸与局部振动 | 清单不支持；正面轻点互动不受影响，触觉只有整机能力 |

## 真机与资料注意点

真机应先经原连接器读取显示信息、显示模式、自动旋转和相机联动状态，再观察完整流程、超时／断连重试、相机抢占、锁屏返回与功耗。验证方向使用左上角 L 形加右下单点等非对称图案；全亮帧无法判断镜像或转置。
